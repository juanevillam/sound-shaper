# UI kit

`src/ui` (imported as `@/ui`) — the app's React Native UI kit: design tokens, a
typed icon set, the Welcome / Settings / Manage-account screens, the iOS sheet
and bar chrome, dialogs, and splash / animation helpers. Built on
[`@expo/ui`](https://docs.expo.dev/versions/latest/sdk/ui/jetpack-compose/) —
Jetpack Compose on Android, SwiftUI on iOS — via Metro's `.ios.tsx`
resolution; the base `.tsx` file is Android and the type source, and both sides
share one prop API.

**Both platforms are first-class.** The kit began Android-first; both sides
were brought to the same native-feel bar in Phase B (closed 2026-09-11), and iOS
stays the reference for the result. Two naming conventions follow from that
(see [`standards.md`](standards.md) → "iOS-only components"): a component with
an Android twin takes the `.ios.tsx` suffix, while one that exists ONLY on iOS
carries `Ios` in its NAME (`SheetFormIos`, `HeaderGlyphButtonIos`) — the type
checker never applies the `.ios` suffix, so a suffixed file with no twin would
need a stub beside it.

`index.ts` is the public surface. Components consumed only inside `src/ui`
(`TextLink`, `AnimatedEntrance`, `SettingsAccountSection`, the screens' prop
types…) are deliberately not exported; re-add one the day something outside
imports it. The kit takes `colors` and already-translated strings as props
rather than reading the app's translator, which is why the screens are
prop-driven.

## Adding an icon

Icons come from Google's [`@expo/material-symbols`](https://www.npmjs.com/package/@expo/material-symbols)
(outlined set, imported per-name so Metro bundles only what's used); a filled
variant would be a local drawable in `src/ui/assets/icons/` generated with its
CLI.

1. In `src/ui/icons.ts`: `import Foo from '@expo/material-symbols/foo.xml';`
   and add `foo: Foo,` to the `icons` map (or
   `require('./assets/icons/foo-filled.xml')` for a filled variant).
2. In `src/ui/AppIcon.ios.tsx`: add the matching SF Symbol to the `SF_SYMBOLS`
   map — **every `IconName` needs both entries** (the map is exhaustively typed,
   so `tsc` reminds you).
3. `IconName` updates automatically — use `iconSource('foo')` or
   `<AppIcon name="foo" />`.

The iOS side is simulator-verified on iPhone 17 / iOS 26.5; every measured
constant in the kit names the device and OS it was band-scanned on.
